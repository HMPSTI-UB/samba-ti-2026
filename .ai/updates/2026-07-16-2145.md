## Restructure `src/features/` folder

Per user request, restructured feature folder from `actions/` to `api/` pattern:

### Before
```
features/auth/actions/login-action.ts ← types inline
features/auth/components/
features/auth/hooks/use-login.ts     ← imports from actions/
```

### After
```
features/auth/api/action.ts          ← server action, imports types
features/auth/types/action.ts        ← extracted types (LoginPayload, LoginActionResult, etc.)
features/auth/components/
features/auth/hooks/use-login.ts     ← imports from api/action
```

### Changes made
- Deleted `src/features/auth/actions/` (including `login-action.ts`)
- Created `src/features/auth/api/action.ts` — server action with `"use server"`, imports types
- Created `src/features/auth/types/action.ts` — extracted `LoginPayload`, `AuthTokens`, `LoginActionResult`
- Updated `src/features/auth/hooks/use-login.ts` import path
- Rewrote `src/features/AGENTS.md` to reflect new `api/` + `types/` structure

### Conventions established
- Server Actions → `api/action.ts`
- Client fetch helpers → separate files in `api/` (e.g., `api/client.ts`)
- Types → separate files in `types/`, never inline
